# 웹 프로젝트 스캐폴딩

새 프로젝트를 실행 가능한 최소 웹 앱과 반복 가능한 AI 작업 환경으로 구성한다. 특정 제품의 화면, 데이터 모델, 외부 서비스 연동을 복제하지 않는다.

## 입력 확인

- 대상 경로와 프로젝트명, 새 디렉터리인지 기존 저장소인지 확인한다. 경로가 없으면 파일 생성 전에 확인한다.
- 기존 파일, 프로젝트 규칙과 패키지 매니저를 읽고 충돌하는 설정을 파악한다. 기존 파일을 일괄 덮어쓰지 않는다.
- 인증, DB, 서버 상태 관리, 폼, 차트, 이메일, AI 연동 중 필요한 기능을 정한다. 요구가 없으면 기본 앱과 최소 하네스만 구성한다.
- 사용할 AI 도구와 팀 실행 지원 여부를 확인한다. 특정 모델명, 운영체제 명령, MCP 서버를 고정하지 않는다.

## 구성 순서

1. [패키지 목록](references/packages.md)을 읽고 기본 패키지와 선택 기능을 분리한다. 패키지 목록과 설치 예시에 구체적인 버전을 적지 않는다. 설치 시 호환성을 확인하고 실제 선택 결과는 생성된 매니페스트와 lockfile로 관리한다.
2. [앱 구조](references/project-layout.md)를 읽고 활성화할 모듈, 생성 파일, 검증 명령을 짧게 정리한다. 실행 요청이면 해당 범위에서 구성하고, 설계·검토 요청이면 문서만 작성한다.
3. pnpm, TypeScript, App Router, Tailwind, Biome 기반의 최소 앱을 만든다. 사용자가 지정한 스택은 우선한다. 설치된 Next.js의 관련 문서를 확인하고, 로컬 문서가 없으면 공식 문서로 보완한다.
4. 요청한 선택 모듈만 추가한다. 폴더와 파일은 실제 사용처가 있을 때 만든다. 공용 라이브러리 초기화와 Provider는 활성화한 기능에 맞춘다.
5. [작업 하네스](references/harness.md)에 따라 공용 규칙, 작업 기록과 검증 기준을 만든다. 기본은 단일 실행 흐름이다. 역할 분리와 협업이 필요한 경우에만 에이전트·오케스트레이터를 추가한다.
6. 아래 검증을 실행하고 생성 파일, 선택 패키지, 결과와 미검증 항목을 대상 프로젝트의 `artifacts/scaffolding/summary.md`에 기록한다. 새 세션에서 읽을 시작점도 적는다.

## 완료 기준

- 설치, 정적 검사, 타입 검사와 프로덕션 빌드가 성공한다. 선택한 테스트 도구는 의미 있는 최소 동작을 확인한다.
- 브라우저에서 시작 페이지와 선택 기능의 기본 흐름을 확인한다. 확인하지 못하면 미검증으로 기록한다.
- 스크립트가 설치된 도구·설정·실제 파일을 가리킨다. 빈 테스트 스위트는 통과 근거로 삼지 않는다.
- 인증·DB 없이 선택한 구성은 외부 서비스의 비밀값 없이 시작되고 빌드된다.
- `.env.example`에는 활성화한 기능의 변수명과 설명만 둔다. 비밀값, 기존 계정과 운영 주소를 복사하지 않는다.
- 원본의 제품명, 도메인 용어, 브랜드 자산, 마이그레이션 이력, 사용자 데이터와 Git 이력을 포함하지 않는다.
- 네트워크·권한·자격증명 때문에 막힌 검증은 실패 원인과 다음 행동을 남긴다. 성공으로 기록하거나 훅을 우회하지 않는다.

## 사용 예시

- "새 폴더에 기본 웹 앱과 단일 에이전트 하네스를 만들어줘."
- "인증, PostgreSQL, 서버 상태 관리와 기능 개발·버그 처리 하네스까지 구성해줘."
- "기존 파일은 유지하고 누락된 테스트 도구와 공용 규칙만 추가해줘."

기존 앱의 화면 수정, 기능 추가와 버그 수정은 해당 프로젝트의 개발 흐름으로 처리한다.
