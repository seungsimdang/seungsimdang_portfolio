# 관리자 UI 개선 디자인 명세

- 작성일: 2026-10-12
- 작업: `admin-ui-refresh` T03
- 근거: `requirements.md`, 현재 `src/app/admin/` 및 `src/components/admin/`, `src/components/layout/navbar.tsx`, `src/app/globals.css`
- 디자인 참조: `artifacts/design-reference/`가 없어 별도 시안은 확인하지 못함

## 목표와 범위

관리자 화면에서 공개 사이트 쉘을 분리하고, 공개 Navbar의 시각 규칙을 이어받는 관리자 헤더를 제공한다. 목록 편집은 순서 draft를 한 번에 저장하도록 하고, 프로젝트 폼은 썸네일 업로드와 편집 가능한 slug를 제공한다.

공개 페이지의 레이아웃, Framer 브레이크포인트, 애니메이션, README의 디자인 참조 값은 유지한다. 공개 화면의 표시명과 이전된 썸네일, 사용자가 바꾼 slug만 요구사항에 따라 갱신된다.

## 사용자 흐름

1. `/admin` 진입은 `/admin/projects`로 이동한다. 인증되지 않은 사용자는 기존 인증 흐름으로 로그인 화면으로 이동한 뒤 원래 목적지 규칙을 따른다.
2. 로그인 화면은 공개 Navbar/Footer 없이 로그인 카드만 표시한다. 로그인 중, 권한 거부, 세션 만료 상태를 카드 안에서 안내한다. 세션이 없는 화면이므로 관리자 탐색 링크와 로그아웃은 표시하지 않는다.
3. 로그인 뒤 고정 관리자 헤더에서 프로필, 프로젝트, 발표를 이동한다. 사이트 보기는 새 탭으로 열고, 로그아웃은 기존 동작을 유지한다.
4. 프로젝트/발표 목록에서 위·아래 이동은 화면의 draft 순서만 바꾼다. 사용자가 저장을 누르면 전체 순서를 한 번 반영한다. 저장하지 않은 draft가 있는 상태에서 화면을 떠나려 하면 저장 또는 변경 폐기를 선택하도록 경고한다.
5. 프로젝트 생성/편집에서 파일을 선택해 썸네일을 업로드한다. 업로드 완료 URL은 폼 draft에만 반영되며 프로젝트 저장을 눌러야 DB 값이 바뀐다. 기존 썸네일 삭제도 같은 폼 저장까지 draft 상태다.
6. 프로젝트/발표 편집에서 slug를 바꾼 뒤 저장하면 공개 주소 변경 경고를 확인한다. 저장 성공 뒤 새 slug의 편집 주소로 이동하고 이전 공개 주소는 리다이렉트 없이 종료된다.

## 공통 셸과 내비게이션

### 공개 화면

- 루트의 공개 Navbar, Footer, `pt-header` 동작과 `<html>`/`<body>`, 전역 CSS 및 Pretendard는 기존대로 유지한다.
- 공개 경로와 메타데이터 템플릿은 유지한다. 프로필 이름 변경은 데이터 값으로 반영하고 화면 구조는 바꾸지 않는다.
- 공개 `Button`과 Framer에서 가져온 브레이크포인트·간격·애니메이션은 수정하지 않는다.

### 관리자 로그인 화면

- `LoginPanel`을 단독 콘텐츠로 배치한다. 공개 헤더, 푸터, 고정 관리자 헤더는 표시하지 않는다.
- 현재 화면의 중앙 폭 제한 카드, 제목, GitHub 로그인, 권한 거부·만료 안내를 유지한다.
- 로그인 진행 중에는 버튼을 비활성화하고 진행 문구를 표시한다. 오류/안내는 기존 `role="alert"` 메시지를 사용한다.
- 로그인 화면에는 생략 링크나 관리자 내비게이션을 추가하지 않는다. 로그인 카드가 페이지의 유일한 작업 영역이다.

### 관리자 고정 헤더

- 공개 Navbar의 외곽 규칙을 따른다: `fixed top-0 left-0 right-0 z-50`, 반투명 검정과 blur, `max-w-content`, `container-padding`, 세로 `py-24`, 아래 1px 구분선.
- 좌측 `profile.name`은 `text-xl font-medium`로 표시하고 `/admin/projects`로 연결한다. DB 이름을 읽지 못할 때는 `admin` 대체 문구를 쓴다.
- 우측 내비게이션은 프로필, 프로젝트, 발표, 사이트 보기, 로그아웃 순서다. 현재 관리자 경로는 `aria-current="page"` 및 밑줄/불투명도 100%로 표시하고, 나머지 링크는 50% 불투명도, hover 시 100%다. 공개 Navbar와 같은 링크 간격을 유지한다.
- 대시보드 메뉴는 두지 않는다. `/admin`은 프로젝트 목록으로 보낸다.
- 810px 이상에서는 이름과 링크가 한 줄에 놓인다. 809px 이하에서는 내비게이션이 다음 줄로 내려갈 수 있으며 가로 스크롤을 만들지 않는다. 이름은 줄바꿈하지 않고, 모든 링크의 실제 터치 영역은 최소 44px로 유지한다.
- 본문은 헤더에 가려지지 않게 시작한다. 92px `pt-header` 값은 현재 공개 헤더 기준값이다. 모바일에서는 링크가 줄바꿈되어 헤더 높이가 늘 수 있으므로 고정 높이 92px를 강제하지 말고 실제 헤더 높이에 맞춰 본문 시작 위치를 확보한다.
- `본문으로 건너뛰기`, 키보드 포커스 표시, 기존 `SignOutButton`, 새 탭 보조 안내를 유지한다. 공개 화면에는 관리자 링크를 노출하지 않는다.

## 프로젝트와 발표 목록

### 목록 구성

- 기존 `AdminPageHeader`에 제목과 우측 생성 링크를 둔다. 생성 링크는 공개 `Button` 대신 `AdminButton`의 동일한 관리자 크기를 사용한다. 위계는 primary로 둔다.
- `SortableList`는 번호, 제목, slug, 보조 정보(프로젝트 기간 또는 발표 날짜·장소), 순서 이동, 행 제목 편집 링크, 삭제 동작으로 구성한다.
- 제목 자체를 편집 화면 링크로 사용한다. 행 안에 별도의 "편집" 버튼을 두지 않는다.
- 위·아래 이동은 시각적으로 작은 ↑/↓ 아이콘을 쓰고 버튼 히트 영역은 44x44px 이상으로 둔다. 접근 가능한 이름은 "{제목} 위로 이동", "{제목} 아래로 이동"이다. 첫 행의 위, 마지막 행의 아래는 비활성화한다.
- 삭제는 "삭제" 텍스트를 유지하고 위험 동작 토큰을 사용한다. 색만으로 상태를 전달하지 않는다. 목록 삭제 전 확인은 기존 관리자 `ConfirmDialog`를 재사용한다.
- 빈 목록은 기존 안내 문구와 관리자 크기의 생성 링크를 표시한다.

### 순서 저장 상태와 흐름

| 상태 | 표시와 동작 |
| --- | --- |
| 변경 없음 | 저장 버튼 비활성, 순서 변경 안내 없음 |
| draft 변경 | "순서가 변경되었습니다. 저장해야 반영됩니다" 안내, 저장 버튼 활성 |
| 저장 중 | 저장과 이동/삭제 버튼 비활성, 목록에 바쁨 상태 표시 |
| 저장 성공 | 서버 기준 순서를 draft로 확정하고 "순서를 저장했습니다"를 `aria-live` 상태로 알림 |
| 저장 실패 | draft 순서를 보존하고 오류와 재시도 가능한 저장 버튼 표시 |
| 목록 충돌 | 지정된 충돌 문구와 새로고침 동작 표시. 새로고침 후 서버 순서를 다시 사용 |

저장은 전체 slug 목록을 한 번에 제출한다. 이동 도중 서버 요청은 하지 않는다. 항목 삭제는 기존처럼 즉시 반영되고, 삭제한 항목을 draft에서 빼되 다른 draft 순서는 보존한다. 항목이 0개 또는 1개면 순서 저장은 활성화되지 않는다.

### 저장하지 않은 순서 이탈 경고

- draft가 서버 순서와 다르면 다른 관리자 링크/헤더 링크, 행 편집 링크, 새 항목 링크로 이동할 때 "저장하지 않은 순서 변경이 있습니다" 확인을 표시한다.
- 선택지는 "계속 머무르기"와 "변경 버리기"다. 기본 포커스는 계속 머무르기에 둔다. 버리고 이동하면 서버에 저장되지 않은 draft만 폐기한다.
- 새로고침, 탭 닫기처럼 문서를 떠나는 경우 브라우저 기본 이탈 경고를 사용한다. 브라우저 뒤로/앞으로 이동도 draft가 사라지지 않도록 경고 대상으로 다룬다.
- 현재 common 컴포넌트에는 이탈 확인 UI가 없다. 관리자 `ConfirmDialog`는 삭제 문구가 고정되어 있어 이탈 경고에 그대로 쓰기 어렵다. 새 Radix 의존성은 추가하지 않는다. 이탈 경고 UI를 위한 컴포넌트 변경 또는 브라우저 기본 확인창 중 구현 선택을 개발자가 정하고, App Router에서 뒤로가기 취소가 실제로 보장되는지 확인해 제한이 있으면 결과에 명시한다.

## 프로젝트·발표 생성 및 편집 폼

- 기존 `ProjectForm`, `TalkForm`, `TextField`, `FormActionBar`, `FormStatus` 구조와 필드 연결·오류 표시 패턴을 유지한다.
- slug 입력은 생성/편집 모두 편집 가능하다. 영문 소문자, 숫자, 하이픈, 64자 제한과 `new` 예약어 검증 오류를 필드에 연결한다. 중복 slug 오류도 slug 필드에 표시한다.
- 수정 중 slug가 바뀌면 저장 전에 기존 주소와 새 주소를 포함한 확인을 표시한다. "이전 주소는 더 이상 열리지 않고 자동 이동도 제공되지 않습니다"를 알린다. 확인 후 저장하고, 성공 시 새 slug 편집 경로로 교체해 이전 편집 URL이 뒤로가기에 남지 않게 한다. slug를 변경하지 않았으면 확인을 띄우지 않는다.
- 프로젝트는 기존 공개 주소 패턴 `/work/{slug}`를 경고에 표시한다. 발표의 공개 상세 경로는 요구사항에서 확인되지 않았으므로 해당 경로가 확인되기 전에는 URL을 추정해 노출하지 말고, API 명세에서 발표 주소 유무와 경고 문구를 확정한다.
- 폼 저장 중에는 저장 버튼을 비활성화하고 기존 진행/성공/오류 안내를 사용한다. slug 충돌과 저장 실패 뒤에는 입력 draft를 보존한다.

## 썸네일 파일 선택과 업로드

대상은 프로젝트 생성/편집 폼이다. 파일 입력에는 보이는 label을 연결하고 PNG, JPG, WebP 및 최대 4MB 제한을 안내한다. 브라우저 선택 필터와 클라이언트 검증은 사용성 지원이며 서버 오류도 같은 필드 아래 읽을 수 있게 표시한다.

| 상태 | 표시와 동작 |
| --- | --- |
| 썸네일 없음 | 파일 선택 입력과 지원 형식/크기 안내 |
| 기존 썸네일 있음 | 현재 이미지 미리보기, 접근 가능한 설명, 썸네일 제거 동작 |
| 파일 선택 | 선택 파일명과 크기 표시. 파일이 유효하지 않으면 업로드하지 않고 구체 오류 표시 |
| 업로드 중 | 진행 상태를 텍스트로 알리고(`role="status"` 또는 `aria-live`), 파일 선택/저장 동작을 중복 제출하지 않게 잠금 |
| 업로드 실패 | 오류 문구와 다시 시도 동작. 기존 DB 값과 현재 썸네일 draft를 유지 |
| 업로드 완료 | 미리보기를 새 파일로 바꾸고 반환 URL을 폼 draft에 반영. DB 저장 전임을 폼의 저장 상태와 일치시킴 |
| 썸네일 제거 선택 | 미리보기 제거를 draft로 표시. 프로젝트 저장 전까지 DB 값은 유지 |

여러 번 업로드하면 마지막 성공 파일만 draft에 반영한다. 생성 폼은 slug 입력 전에도 파일을 올릴 수 있다. 이탈 시 저장되지 않은 썸네일 변경에 별도 확인을 추가하지 않는다. 이는 기존 폼 동작과 같으며 업로드된 미참조 Blob 정리는 범위 밖이다.

## 프로필 화면과 공개 화면 데이터 변경

- 프로필 편집 화면은 기존 필드와 동작을 유지한다. 이름 변경은 이번 작업에서 공개 데이터의 `profile.name`을 "SeungHyun Lee"로 바꾸는 운영 변경이며, 관리자 폼에 새 옵션이나 상수 텍스트를 추가하지 않는다.
- 공개 Navbar, 히어로, 푸터, 페이지 제목 메타데이터는 DB 프로필 이름을 표시한다. 썸네일은 공개 프로젝트 카드 등 현 사용처에서 기존 경로와 Blob URL 모두 렌더 가능한 상태를 유지한다.
- 공개 썸네일 로딩 실패는 페이지 전체 오류가 아니라 썸네일 영역의 실패/빈 상태로 제한한다. 공개 레이아웃과 카드 스타일 변경은 이 명세 범위가 아니다.

## 접근성 및 반응형

- 헤더와 목록 조작은 키보드로 접근할 수 있고 포커스 표시를 유지한다. 활성 관리자 경로에는 `aria-current="page"`를 제공한다.
- 아이콘 전용 이동 버튼은 제목과 방향을 포함한 `aria-label`을 갖고 44x44px 이상의 터치 영역을 확보한다.
- 업로드, 저장, 오류, 삭제 성공과 목록 순서 변경은 기존 `FormStatus` 및 상태 영역 패턴으로 스크린 리더에 알린다. 색상만으로 상태를 전달하지 않는다.
- 모든 폼 입력은 연결된 label을 가지며 오류는 `aria-invalid`/`aria-describedby`로 연결한다. 파일 입력에도 같은 규칙을 적용한다.
- 810px 전후는 기존 Framer 경계로 유지한다. 관리자 헤더는 좁은 화면에서 줄바꿈하고, 목록 행과 폼 액션은 세로로 흐르게 하며 가로 스크롤을 만들지 않는다. 기존 Framer 간격과 공개 애니메이션은 변경하지 않는다.

| 영역 | 현재 컴포넌트 | 디자인 적용 |
| --- | --- | --- |
| 페이지 제목 | `AdminPageHeader` | 목록/폼 제목과 주 작업 링크 유지 |
| 관리자 링크/버튼 | `AdminButton` | 관리자 크기 `min-h-44 px-20 text-small`로 통일 |
| 관리자 내비게이션 | `AdminNav` | 대시보드 제거, 활성 링크 상태와 44px 히트 영역 유지 |
| 삭제 확인 | `ConfirmDialog` | 프로젝트/발표/목록 삭제에 재사용 |
| 사이트 외부 이동 | `ExternalLink` | "사이트 보기"에 재사용해 새 탭 안내 유지 |
| 폼 저장 상태 | `FormStatus`, `FormActionBar` | 기존 저장/취소/오류 흐름 유지 |
| 공통 인터랙션 | `src/components/common/` | 확인 대화상자는 없음. `ExternalLink`는 존재하나 링크 이동용이다. |

`radix-ui`는 `package.json` 의존성에 없다. 이 명세는 Radix 추가를 전제하지 않는다. 필요한 상호작용은 브라우저 기본 입력/확인 UI 또는 기존 관리자 컴포넌트로 구성한다.

## 운영 항목과 화면 영향

- 빌드 시 DB 마이그레이션(F10)은 배포 동작이며 새로운 사용자 화면을 만들지 않는다. 실패 시 배포가 중단되고 기존 배포가 계속 서비스된다.
- 기존 썸네일 이전(F11)은 사용자 화면 없이 실행되는 운영 작업이다. dry-run에서 대상과 파일을 확인하고, 운영 실행 뒤 공개 이미지 표시를 확인한 다음에만 이전된 원본 파일과 스크립트를 제거한다.
- Production의 프로필 이름 변경과 썸네일 이전은 사용자 확인 절차를 거친 운영 데이터 변경이다. 미리보기/확인 결과를 제시하기 전 실행하지 않는다.

## 후속 명세에서 확인할 점

- F6의 브라우저 뒤로가기 경고가 Next App Router 탐색에서 취소 가능한지 구현 단계에서 확인하고, 제한과 실제 보장 범위를 기록한다.
- F7 공개 썸네일의 실제 렌더링 컴포넌트와 허용할 Blob 호스트를 API 명세/구현에서 확정한다.
- F9 발표 slug 변경 경고에 표시할 공개 URL이 존재하는지 확인한다. 확인 전 URL 패턴을 가정하지 않는다.
- TaskCreate/TaskUpdate 원본 도구는 이 세션에서 사용할 수 없어 태스크 상태 갱신은 수행하지 못했다. 작업 시작/완료는 orchestrator에 협업 메시지로 전달한다.
