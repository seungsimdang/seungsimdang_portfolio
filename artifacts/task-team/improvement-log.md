# 개선 기록

- 사이클 시작 시 산출물을 `artifacts/task-team/` 최상위에 만들어 README의 `<work-id>/` 계약과 어긋남. 원인은 `task-team-orchestrator` SKILL.md의 산출물 경로가 사이클 폴더 없이 적혀 있는 점. 사이클 도중 `<work-id>/` 폴더로 이동(`13cf1ff`)했으나, 이동 이유였던 재리뷰 확인 훅을 삭제한 뒤 사용자 지시로 최상위로 되돌림(`014abde`). 훅 삭제 시점에 이동 유지 여부를 다시 확인했어야 함.
- 사이클 폴더 불일치로 재리뷰 확인 훅이 다른 사이클 리뷰 5개를 세어 오경고를 냄. 사용자 지시로 훅 삭제.
- isolation worktree는 마지막 커밋에서 분기되므로, 미커밋 산출물을 읽으라고 지시한 재작업이 한 번 발생함. 스폰 전에 지시문이 참조하는 산출물을 먼저 커밋.
- 마크다운 줄바꿈 검사기는 인덱스(`git show :file`)를 읽으므로, 작업 파일만 고치며 반복 실행하다 줄을 과도하게 합친 실수가 있었음. 수정 후 다시 스테이징하고 검사.
- `package.json`만 미스테이징 상태로 두면 React Doctor `--staged`가 커밋을 막음. 의존성 커밋을 먼저 분리해 해결.
- 리뷰어가 저장했다고 보고한 `code-review-2.md`가 실제로 없었음. 이후 리뷰 지시에 저장 후 존재 확인을 넣었고 재발 없음.
- worktree 구현자에게는 `.env.local` 읽기가 막혀 DB 동작 확인을 orchestrator가 메인 체크아웃에서 읽기 전용으로 수행.
