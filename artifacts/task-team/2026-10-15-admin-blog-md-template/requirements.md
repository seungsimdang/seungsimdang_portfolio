# requirements: admin 블로그 새 글 .md 템플릿 다운로드

- work-id: `2026-10-15-admin-blog-md-template`
- 입력: `00-input.md`
- 작성: project-manager (T02)
- 상태: 사용자 확정 대기 (아래 "사용자 확정 필요" 1~6)

## 1. 목적과 범위

- `/admin/blog/new`에서 .md 템플릿을 내려받아 로컬에서 작성하고, 기존 ".md 가져오기"로 다시 불러오는 왕복 흐름을 제공한다.
- 범위 내: 새 글 화면의 템플릿 다운로드 진입점, 템플릿 내용, 다운로드 파일명, 가져오기 안내 문구 보강.
- 범위 밖: 가져오기 파서·슬러그 규칙 변경, 서버 API·DB 변경, 템플릿 편집 기능, 새 의존성, 공개 페이지 변경.

## 2. 현재 동작 (코드 확인 기준)

- `parsePostMarkdown`(`src/lib/blog/frontmatter.ts`)은 `title`, `categories`, `tags`, `date`, `published`만 읽는다. 그 외 키는 버린다. `published`는 `false`일 때만 `unpublished`로 표시되어 "저장하면 공개 글이 됩니다" 경고를 띄운다.
- 프론트매터 펜스 정규식은 첫 `---` 줄 이후 가장 가까운 `\n?---`에서 끝난다. 프론트매터 내부(주석 포함)에 `---` 문자열이 있으면 조기 종료된다.
- YAML 파싱은 `schema: "core"`라 `#` 주석은 허용되고 날짜는 문자열로 읽힌다.
- `applyImport`(`blog-form.tsx`)의 우선순위
  - 제목: frontmatter `title`이 비어 있으면 파일명(날짜 접두 제거) 으로 대체된다.
  - 날짜: 파일명 날짜 접두 > frontmatter `date` > 오늘(Asia/Seoul).
  - slug: 파일명에 날짜 접두가 있으면 파일명 전체, 없으면 `{날짜}-{제목}`을 `slugifyPostName`으로 변환.
- 가져오기는 `.md`/`.markdown`, UTF-8, 1MB 이하만 허용한다. 입력이 이미 있으면 덮어쓰기 확인창을 띄운다.
- 새 글 화면 상단 ".md 가져오기" 블록은 `!isEdit`에서만 렌더된다. 버튼 배치는 `flex flex-wrap items-center gap-12`.

## 4. 수용 기준 (검증 가능)

### F1 버튼

- AC1-1: `/admin/blog/new`에 "템플릿 다운로드" 버튼이 보이고 키보드(Tab, Enter/Space)로 동작한다.
- AC1-2: 버튼은 `<button type="button">`이어서 클릭해도 폼 제출·이탈 확인(LeaveDialog)·폼 값 변화가 없다.
- AC1-3: 모바일(767px 이하)과 데스크톱(768px 이상) 경계 양쪽에서 "파일 선택"과 같은 줄에 두거나 자연스럽게 줄바꿈되고 가로 스크롤·잘림이 없다 (postmortem-20261015145447 재발 방지 항목: 모바일 flex 줄바꿈, 767/768px 검증).
- AC1-4: 새 글 화면에서만 노출된다 (항목 6 권장안 기준). `/admin/blog/[slug]`에는 없다.

### F2 다운로드

- AC2-1: 클릭하면 브라우저 다운로드가 시작되고 파일명은 항목 2 확정안과 같다.
- AC2-2: 파일은 UTF-8(BOM 없음), LF 줄바꿈, 확장자 `.md`. MIME은 `text/markdown`.
- AC2-3: 서버 요청·DB 접근이 없다 (항목 5 권장안). 로그인 세션 만료 상태에서도 클릭 동작은 영향받지 않는다.
- AC2-4: 다운로드에 쓴 임시 URL은 사용 후 해제한다 (메모리 누수 방지).
- AC2-5: 프로덕션 CSP 아래에서 다운로드가 차단되지 않는다 (QA에서 `pnpm build` 후 확인 또는 CSP 지시문 검토).

### F3 왕복

- AC3-1: 템플릿 원문을 `parsePostMarkdown`에 넣으면 `error`가 없고 `unpublished`가 없다.
- AC3-2: 템플릿의 프론트매터 키는 파서가 인식하는 키만 쓴다 (항목 1 확정안).
- AC3-3: 템플릿을 그대로(수정 없이) 가져오면 "파일을 불러왔습니다" 성공 토스트가 뜨고 경고·오류 토스트가 없다.
- AC3-4: 템플릿의 `title`, `categories`, `tags`, 본문을 채워 가져오면 폼의 제목, 카테고리 칩, 태그 칩, 본문에 값이 그대로 들어간다. 저장 시 `postCreateFormSchema` 검증을 통과한다 (slug 규칙, 제목 1~200자, 카테고리 10개·태그 20개 이하, 각 50자 이하).
- AC3-5: 템플릿에 들어가는 `date` 값은 `YYYY-MM-DD` 형식이며 `isRealDate`를 통과한다.
- AC3-6: 프론트매터 영역 안에 `---` 문자열(주석 포함)이 없다 (펜스 조기 종료 방지).
- AC3-7: 템플릿의 안내 주석은 YAML `#` 주석으로만 두어 가져온 뒤 본문(`content`)에 남지 않는다 (항목 3 권장안).
- AC3-8: 다운로드한 파일명 그대로 가져와도 날짜·slug가 의도와 다르게 덮이지 않는다 (항목 2 권장안에서 충족).

### F4 안내 문구

- AC4-1: 기존 문구("frontmatter(title, categories, tags)와 본문을 폼에 채웁니다...")가 템플릿 흐름과 모순되지 않는다. 날짜는 frontmatter `date`도 읽으므로 인식 키 목록이 실제 파서와 일치한다.

## 5. Edge case

1. 템플릿 `title`이 빈 값이면 `applyImport`가 파일명(예: `blog-post-template`)을 제목으로 쓴다. 사용자가 제목을 안 쓰고 가져와도 오류 없이 파일명이 제목이 되는 점을 인지해야 한다. 템플릿은 제목 자리에 눈에 띄는 예시 문구를 두어 이 상황을 줄인다 (항목 3).
2. 날짜 접두 파일명(`YYYY-MM-DD-제목.md`)으로 내려받으면 파일명 날짜가 frontmatter `date`보다 우선한다. 사용자가 frontmatter 날짜만 고치면 조용히 무시된다. 이것이 항목 2에서 고정 이름을 권장하는 이유다.
3. 사용자가 파일명을 날짜 접두 형식으로 바꾸면 slug는 파일명 전체로 제안된다. 이는 기존 동작이며 변경하지 않는다.
4. 날짜는 클라이언트 현재 시각이 아닌 Asia/Seoul 기준 오늘이어야 한다 (`todayInSeoul` 기준, 폼 기본 발행일과 일치). 자정 전후 불일치 방지.
5. `categories`/`tags`를 `[]`로 두면 빈 목록, 문자열 단일 값은 배열로 승격된다. 항목에 숫자만 있어도 문자열로 변환된다.
6. 사용자가 `published` 키를 추가해도 `false`가 아니면 무시, `false`면 경고 토스트 후 공개 글로 저장된다 (기존 동작, 이번 범위 아님).
7. 폼에 이미 입력이 있을 때 템플릿을 내려받아도 폼은 변하지 않는다. 가져오기 시점에만 덮어쓰기 확인창이 뜬다.
8. 한글 파일명 NFC/NFD 차이: 파일명은 ASCII(고정 영문명)로 두어 OS별 정규화 문제를 피한다.
9. 다운로드 중복 클릭: 매번 같은 내용·이름으로 저장되며 상태가 남지 않는다 (유일성 보장 불필요, 서버 생성 없음).
10. 본문 이미지는 가져오기로 올라가지 않는다 (기존 안내 유지). 템플릿에 이미지 문법 예시를 넣을 경우 존재하지 않는 경로 이미지가 본문에 남지 않아야 한다.
11. 호출부·props: 새 데이터 전달은 없다. 템플릿 상수·생성 함수는 `blog-form.tsx` 내부(새 글 분기)에서만 사용한다. 새 컴포넌트를 만들면 props는 없는 형태가 바람직하다.

## 6. 비기능 요구사항

- 새 의존성 추가 금지. 서버 코드·DB 스키마·마이그레이션 변경 없음.
- 접근성: 버튼은 텍스트 레이블 포함, 포커스 표시 유지, 기존 `AdminButton` 스타일 사용.
- 기존 Framer 디자인·브레이크포인트 보존. 스타일은 `tailwind.md` 규칙을 따른다.
- 파일명 kebab-case, 주석·문서에 em-dash 금지, 주석은 명사형 종결(`project-structure.md` 6번).
- 테스트는 QA가 T09에서 작성한다. 이 단계에서 담당 배정 없음. 개발자는 커밋하지 않는다.
- 능동 트리거(크론, 알림), 배포 자동화, 환경변수, 목록 일부 표시 문구는 해당 없음. 다운로드는 사용자 클릭이 유일한 트리거다.

## 7. 사용자 확정 필요 (모호 항목 1~6)

각 항목은 권장안 하나를 제시한다. 확정 전에는 구현하지 않는다.

### 1. frontmatter 키 범위 - 사용자 확정 필요

- 권장: `title`, `date`, `categories`, `tags` 4개만. `published`는 넣지 않는다.
- 근거: 파서가 인식하는 키 중 폼에 반영되는 것은 이 4개다. `published`는 직전 사이클(`2026-10-15-admin-blog-ux`)에서 기능과 DB 컬럼이 삭제됐고, `true`는 파서가 무시하며 `false`는 "공개 글이 됩니다" 경고만 유발한다. 템플릿에 넣으면 삭제된 기능이 남아 있는 것처럼 보인다.

### 2. 다운로드 파일명 - 사용자 확정 필요

- 권장: 고정 이름 `blog-post-template.md`(ASCII). 날짜 접두 형식은 파일 안내 주석으로만 설명한다.
- 근거: 파일명 날짜 접두는 frontmatter `date`보다 우선하므로(`applyImport`) 오늘 날짜 접두 파일은 사용자가 frontmatter 날짜를 고쳐도 무시된다. 고정 이름이면 날짜·slug가 `{frontmatter date}-{title}`로 제안되어 왕복이 손실 없이 동작한다. ASCII라 OS별 한글 정규화 문제도 없다.

### 3. 본문 내용 - 사용자 확정 필요

- 권장: 안내는 frontmatter 안의 YAML `#` 주석(파서가 버림)으로만 쓰고, 본문은 짧은 제목·문단 자리 표시만 둔다. HTML 주석(`<!-- -->`)과 문법 예시 모음은 넣지 않는다. 안내 주석에는 `---`를 쓰지 않는다. `title`에는 눈에 띄는 예시 문구, `date`에는 Asia/Seoul 오늘 날짜, `categories`/`tags`에는 예시 값 1~2개를 둔다.
- 근거: 본문의 HTML 주석이나 예시는 가져오기 후 `content`로 그대로 저장되어 공개 글에 섞일 위험이 있다. YAML 주석은 파싱에서 제거되어 안전하다. 빈 `title`은 파일명이 제목이 되는 함정이 있어 예시 문구가 낫다.

### 4. 데이터 소스 - 사용자 확정 필요

- 권장: 정적 상수(코드 내 고정 문자열, 날짜만 다운로드 시점에 채움). DB·admin 편집 기능은 만들지 않는다.
- 근거: 템플릿은 파서 인식 키에 종속되어 코드 변경과 함께 바뀌어야 하며(왕복 보장), 편집 가능하게 하면 파서와 어긋난 템플릿이 생길 수 있다. 스키마·API·마이그레이션 비용이 이번 요청 범위를 넘는다. 메모리 규칙상 사용자 확인이 필요하다.

### 5. 생성 방식 - 사용자 확정 필요

- 권장: 클라이언트 Blob 다운로드(`<a download>` + 임시 URL, 사용 후 해제). `public/` 정적 파일과 API 라우트는 쓰지 않는다.
- 근거: 오늘 날짜를 채우려면 클릭 시점 생성이 필요하다. 정적 파일은 날짜를 고정할 수 있어 낡고, 공개 경로에 노출된다. API 라우트는 인증·응답 형식·테스트 부담이 늘지만 얻는 것이 없다. 새 의존성이 필요 없다. 구현 방식 세부는 개발자 영역이며 CSP 확인(AC2-5)만 요구한다.

### 6. 편집 화면 노출 - 사용자 확정 필요

- 권장: 새 글 화면에만 노출한다.
- 근거: ".md 가져오기"가 새 글에서만 존재(`!isEdit`)하므로 편집 화면에서는 템플릿을 다시 불러올 방법이 없어 혼란만 준다. 요청 원문도 "새글 추가 시"로 한정한다.

## 8. 확인 필요 (추가)

- 템플릿의 예시 카테고리·태그 값을 어떤 문구로 할지 (예: 실제 운영 카테고리명). 기본은 일반적인 예시 문구, 최종 문구는 디자이너/사용자 확인.
- 버튼 레이블 최종 문구 ("템플릿 다운로드" 권장).
