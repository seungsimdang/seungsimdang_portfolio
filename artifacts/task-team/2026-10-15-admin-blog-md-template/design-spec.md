# design-spec: admin 블로그 새 글 .md 템플릿 다운로드

- work-id: `2026-10-15-admin-blog-md-template`
- 입력: `requirements.md` (끝의 "사용자 확정" 섹션 우선)
- 작성: designer (T03)
- 범위: `/admin/blog/new`의 ".md 가져오기" 블록만. 편집 화면, 서버, 공개 페이지 변경 없음.

## 1. UX 흐름

1. 관리자가 새 글 화면에서 "템플릿 다운로드" 클릭 -> `blog-post-template.md` 저장.
2. 로컬에서 title, date, categories, tags, 본문 작성.
3. "파일 선택"으로 불러오기 -> 기존 `importFile`/`applyImport` 흐름 그대로(덮어쓰기 확인창, 성공 토스트).

템플릿 다운로드는 폼과 무관한 독립 동작이다.

## 2. 컴포넌트와 배치

기존 블록(`!isEdit` 분기의 `space-y-8` 컨테이너) 구조를 유지한다.

```
.md 가져오기                         (p.text-small)
안내 문구                            (p.text-small.opacity-70)
[파일 선택] [템플릿 다운로드] 선택한 파일: xxx.md   (flex flex-wrap items-center gap-12)
```

- 순서: "파일 선택" -> "템플릿 다운로드" -> "선택한 파일: ..." 텍스트. 주 동작(파일 선택)을 앞에 두고 보조 동작을 뒤에 둔다.
- 컨테이너: 기존 `flex flex-wrap items-center gap-12` 그대로. 간격 12px 유지, 새 간격 값 없음.
- 컴포넌트: 기존 `AdminButton`(`src/components/admin/admin-button.tsx`) 재사용. variant는 기본값 `secondary`(두 버튼 동일 시각 무게). `type`은 기본 `button`이므로 제출 없음.
- 새 클래스, 색, 토큰, 컴포넌트 추가 없음. `src/components/common/`에는 버튼/모달류가 없고(category-tabs, pagination 등 공개 화면용), 이번 변경에 새 인터랙티브 primitive는 필요 없다. Radix 불필요.
- 레이블: "템플릿 다운로드" (확정 권장 문구). 아이콘 없음(확인된 아이콘 세트 없음).
- 접근성 이름: 텍스트 레이블로 충분, 별도 `aria-label` 없음. 포커스 링은 `AdminButton` 기존 `focus-visible` 스타일 사용. Tab 순서는 파일 선택 -> 템플릿 다운로드.

## 3. 안내 문구 변경안 (전문)

기존:

> frontmatter(title, categories, tags)와 본문을 폼에 채웁니다. 저장은 직접 눌러야 합니다. 본문 이미지는 자동으로 올라가지 않으니 필요하면 본문의 이미지 삽입을 사용하세요.

변경:

> 템플릿을 내려받아 작성한 뒤 파일 선택으로 불러오세요. frontmatter(title, date, categories, tags)와 본문을 폼에 채웁니다. 저장은 직접 눌러야 합니다. 본문 이미지는 자동으로 올라가지 않으니 필요하면 본문의 이미지 삽입을 사용하세요.

- 변경점: 맨 앞에 템플릿 흐름 한 문장 추가, 인식 키 목록에 `date` 추가(AC4-1).
- 스타일 클래스(`text-small opacity-70`)와 `<p>` 구조는 그대로. 줄바꿈은 자연 줄바꿈.
- 하이픈 없는 평문, em-dash 없음.

## 4. 클릭 인터랙션

- 클릭 즉시 브라우저 다운로드 시작. 파일명 `blog-post-template.md`.
- 토스트: 띄우지 않는다. 이유는 다운로드 표시를 브라우저가 이미 하고, 토스트는 폼의 "불러왔습니다" 성공 토스트와 혼동되며, 실패 경로가 없다(서버 요청 없음).
- 폼 상태: 변화 없음. 값, dirty 상태, LeaveDialog, 덮어쓰기 확인창, `importedName` 표시 모두 영향 없음.
- 버튼 상태: 로딩/비활성 없음. 연타 시 매번 같은 파일(상태 없음).
- 날짜: 클릭 시점의 Asia/Seoul 오늘(`todayInSeoul` 기준)을 `date`에 채움.

## 5. 템플릿 파일 내용 전문

파일명 `blog-post-template.md`, UTF-8(BOM 없음), LF, 끝에 개행 1개. `{오늘}`만 다운로드 시점에 `YYYY-MM-DD`(Asia/Seoul)로 치환한다. 아래 코드 블록이 파일 원문이다.

````
---
# 이 블록의 # 줄은 안내이며 불러올 때 무시됩니다
# title: 글 제목입니다. 비워 두면 파일명이 제목이 됩니다
# date: YYYY-MM-DD 형식입니다. 파일명 앞에 날짜를 붙이면 파일명 날짜가 우선합니다
# categories, tags: 여러 개는 쉼표로 구분하고 각각 따옴표로 감쌉니다
# 이 블록 안에는 줄 구분선 문자열을 쓰지 마세요
title: "글 제목을 입력하세요"
date: {오늘}
categories: ["카테고리 예시"]
tags: ["태그 예시1", "태그 예시2"]
---

## 소제목

본문을 작성하세요.
````

설계 근거와 검증 포인트:

- 키는 title, date, categories, tags 4개만. `published` 없음.
- 안내는 프론트매터 안의 YAML `#` 주석뿐이라 파싱에서 제거되어 `content`에 남지 않는다(AC3-7).
- 프론트매터 구간(첫 `---` 이후 닫는 `---` 전)에 `---` 문자열이 없다. 위 주석 문구에서 "줄 구분선"으로 돌려 말하고, `YYYY-MM-DD` 같은 단일 하이픈만 사용했다. 구현 시 주석 줄에 하이픈 3개 연속이 들어가지 않는지 테스트로 확인한다(AC3-6).
- 주석의 쉼표, 콜론은 `#` 뒤라 YAML 값으로 해석되지 않는다.
- 값은 큰따옴표 문자열 또는 flow 배열이라 `schema: "core"`에서 날짜가 문자열로 읽힌다. `date`는 따옴표 없이도 문자열이어야 하므로 구현자는 파서 결과가 문자열임을 테스트로 확인한다(안 되면 `"{오늘}"`로 감싸는 것이 대안).
- 제목 예시 문구는 비어 있는 title 함정(파일명이 제목이 되는 경우)을 피한다. 수정 없이 가져오면 제목 "글 제목을 입력하세요", 카테고리 칩 1개, 태그 칩 2개, 본문 "## 소제목" 문단이 채워지고 성공 토스트만 뜬다(AC3-3).
- 본문은 이미지, HTML 주석, 문법 예시 없음. 자리 표시 두 줄뿐.
- 예시 카테고리, 태그 문구는 일반 예시 문구다. 실제 운영 카테고리명으로 바꾸려면 사용자가 지정한다(미확정 항목).

## 6. 반응형 기준 (767px / 768px 경계)

근거: postmortem-20261015145447 재발 방지(모바일 flex 줄바꿈, 767/768 검증). 이 블록은 단일 컬럼 폼 안에 있고 브레이크포인트별 분기가 없다. 별도 `md:` 클래스를 추가하지 않는다.

- 컨테이너 `flex flex-wrap items-center gap-12`가 두 버튼과 "선택한 파일" 텍스트를 줄바꿈으로 수용한다.
- 버튼 높이 `min-h-44`, 좌우 `px-20` 유지(터치 타겟 44px).
- 767px(모바일 최소 콘텐츠 폭 기준, 예: 360~767px)
  - 두 버튼의 폭 합이 가용 폭보다 작으면 한 줄, 넘치면 "템플릿 다운로드"가 아래 줄로 내려간다. 버튼 내부 텍스트는 줄바꿈되지 않고(버튼은 inline-flex, 한 줄 레이블) 가로 스크롤과 잘림이 없어야 한다.
  - "선택한 파일: 긴파일명.md"는 버튼 뒤에서 자연 줄바꿈된다. 긴 파일명은 폼 폭 안에서 줄바꿈되어 가로 스크롤을 만들지 않아야 한다(기존 동작과 동일하며 구현자는 360px에서 육안 확인).
- 768px(데스크톱 시작): 같은 줄에 두 버튼과 파일명 텍스트가 배치된다. 줄바꿈 상태가 767px과 달라도 높이 점프 외 시각 깨짐이 없어야 한다.
- 검증 방법: 767px와 768px 폭에서 각각 스크린샷 확인. 확인 항목은 (a) 문서 가로 스크롤 없음, (b) 버튼 레이블 한 줄 유지와 잘림 없음, (c) 줄바꿈 시 행 간격이 gap-12(12px)로 유지, (d) "선택한 파일" 텍스트 포함 상태에서도 동일.

## 7. 구현자에게 넘기는 제약 요약

- 변경은 `blog-form.tsx` 새 글 분기와 템플릿 상수/생성 로직(위치는 개발자 판단)뿐. 기존 디자인, 픽셀값, 클래스 변경 없음.
- 새 의존성 없음. 서버 요청 없음. 커밋은 orchestrator 담당.
