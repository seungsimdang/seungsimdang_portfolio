## 새 finding

### N-1. `_`, `*` 일괄 제거로 식별자 훼손 (Low)

- 위치: `src/lib/blog/excerpt.ts:13` (`/[`*_~|]/g`)
- 근거: 강조 기호 제거 목적이지만 `use_state`, `a*b`, `snake_case` 같은 본문 텍스트의 기호도 지워져 `usestate` 식으로 나옴. 개발/알고리즘 글이라 발생 빈도가 낮지 않음.
- 영향: description 문구가 일부 어색해질 뿐 동작 오류 아님. 파일 주석이 "일부 기호가 남을 수 있음"만 적고 반대 방향(과제거)은 적지 않음.
- 수정 제안: 필수 아님. 고치려면 단어 경계 기준(`/(^|\s)[*_]+|[*_]+(\s|$)/g`)으로 좁힘. 또는 현 상태 유지하고 ponytail 주석에 과제거도 명시.

### N-2. 정규식 한계 모음 (Low)

- 위치: `src/lib/blog/excerpt.ts:8-13`
- 근거와 영향:
  - 닫히지 않은 코드 펜스는 본문 코드가 요약에 노출됨.
  - `<[^>]+>`는 "a < b ... c > d" 같은 비교 연산자 구간을 태그로 보고 통째로 삭제함.
  - 표 구분행 `|---|---|`은 `|`만 지워져 `---`가 남음.
  - 참조형 링크 `[text][id]`는 대괄호가 남음.
- 수정 제안: 필수 아님. 파일 주석(`ponytail:`)이 정규식 근사의 한계를 이미 선언했으므로 수용 가능. 정확도가 문제 되면 주석대로 mdast 텍스트 추출로 교체.

### N-3. 160자 절단이 서로게이트 쌍을 가를 수 있음 (Low)

- 위치: `src/lib/blog/excerpt.ts:16`
- 근거: `slice(0, 159)`는 UTF-16 코드 유닛 기준이라 159번째 위치가 이모지 중간이면 lone surrogate가 남아 `�`로 렌더될 수 있음.
- 수정 제안: 필수 아님. 필요하면 `Array.from(text).slice(0, 159).join("")`.

## 확인 항목 결과

- 코드 펜스/HTML/이미지/링크/머리말 제거: 순서가 올바름. 코드 펜스를 먼저 지워 코드 안의 `<`, `#`가 영향을 주지 않고, 이미지(`![]()`)를 링크보다 먼저 처리해 `!`가 남지 않음.
- 160자 제한: 절단 시 `…` 포함 최대 160자라 상한 준수. `trimEnd`로 말미 공백 정리됨.
- 빈 결과 title 대체: 상세에서 적용됨(이미지/코드만 있는 글 대응).
- 백트래킹: 중첩 수량자·교대 없음. 모든 패턴이 단일 문자 클래스 기반 선형 스캔이라 치명적 백트래킹(ReDoS) 없음. 다만 `<[^>]+>`와 `` ```[\s\S]*?``` ``는 닫는 기호가 없을 때 여는 기호마다 끝까지 스캔해 최악 O(n^2). 입력이 admin 작성 본문이라 신뢰 경계 안이고 글 길이도 제한적이라 실사용상 문제 없음.
- 주석 규칙: 명사형 종결(`사용`, `교체`), em-dash 0건, 한 줄 한 문장, 줄 끝 쉼표/조사 없음, 사이클 한정 식별자 0건. 규칙 위반 없음.
- 호출부: `generateMetadata`는 이미 조회한 `post`를 재사용하므로 prop/인자 누락 경로 없음.
