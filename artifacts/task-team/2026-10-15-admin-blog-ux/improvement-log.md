# improvement-log: admin·블로그 UX 개선

- 작성: orchestrator, 2026-10-15

## 이번 사이클에서 드러난 점

- 사용자 메시지에 "다시 보고해" 항목과 "나머지 진행" 지시가 섞였는데, 보고 없이 브랜치를 만들고 진행 작업에 들어가 지적받음. 보고 요청이 있으면 보고를 먼저 하고 턴을 끝내야 함(메모리 `report-before-work` 기록).
- 선행 사이클 requirements의 사실 전제("원본에 `published: false` 글 존재")를 원본으로 확인하지 않아 필요 없는 기능이 만들어졌음. requirements의 근거 사실은 원본 데이터로 확인한 결과만 적어야 함.
- 선행 구현이 design-spec의 "작성/미리보기 탭"을 버튼 두 개로 다르게 구현했는데 리뷰에서 잡히지 않음. 리뷰의 수용 기준 표가 design-spec의 컴포넌트 형태까지 대조해야 함.
- requirements는 "코드 먼저, 마이그레이션 나중"을 정했지만 build가 마이그레이션을 자동 적용한다는 사실을 몰라 한 커밋에 넣는 구조였음. T04가 `package.json`·`migrate.mjs`를 확인해 2단계 배포로 바로잡음. 스키마 변경이 있는 요구사항은 T02 단계에서 마이그레이션 적용 경로를 확인해야 함.
- popstate 가로채기를 Chromium 최소 페이지로만 검증해 실제 Next 라우터 리스너 순서를 놓쳤고, 재작업에서 Navigation API로 바꿈. 라우터와 얽힌 브라우저 동작은 실제 앱(또는 같은 라우터를 쓰는 페이지)에서 검증해야 함.
- 커밋 메시지 제목과 본문 사이 빈 줄을 빼 첫 커밋 제목에 본문 전체가 붙음. amend로 바로잡음.
- E2E seed가 기존 행을 건너뛰어 픽스처에서 지운 행이 E2E DB에 남아 QA 단언을 방해함.
