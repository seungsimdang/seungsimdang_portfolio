# 포스트모텀 Candanta 썸네일 상단 문구 잘림

## 버그 요약
- 관련 티켓: `ticket.md`
- 결함 위치: `localize.md` 참조
- 수정: Candanta 카드만 썸네일을 상단 정렬하고 이미지 폭을 카드 높이 기준으로 제한했다 (`fix.md`).
- 결과: 세 뷰포트의 홈·프로젝트 목록 6개 조합에서 제목·설명 표시 및 제목 겹침 검사를 통과했고, 다른 프로젝트 중앙 정렬도 확인했다.

## 원인 유형
- 분류: 테스트 누락
- 원인: 원본 업로드와 HTML·해시 검증으로 썸네일이 등록된 것은 확인했지만, 카드의 실제 크롭 결과와 상단 카피 노출은 확인하지 않았다. `object-cover`의 중앙 정렬로 세로 이미지 상단이 잘렸고, top 정렬만 적용한 경우에도 1440×900 홈 카드에서는 설명이 계속 잘리는 것을 확인했다.

## 패턴 분석
- 이전 유사 사례: `artifacts/bug-team/2026-10-13-admin-save-feedback/postmortem.md`에는 브라우저 확인이 빠진 검증 공백이 기록돼 있다. 화면 영역은 다르지만 정적 증거만으로 사용자에게 보이는 결과를 확인하지 못한 절차상 유사 패턴이다.
- 반복 여부: 검증 공백 패턴 반복. 썸네일 크롭 문제 자체는 첫 발생.

## 재발 방지 항목
1. 썸네일의 위치나 크롭 방식을 바꾸면 원본 파일·HTML·해시 확인만으로 완료 처리하지 않는다. 홈과 목록에서 실제 브라우저 화면을 확인하고, 상단 제목·설명 전체가 카드 안에 보이며 카드 제목과 겹치지 않는지 검증한다.
2. 반응형 카드 검증은 모바일·태블릿·데스크톱 화면을 포함한다. 단순 상단 정렬의 적합성을 가정하지 말고, 가장 넓은 홈 카드에서도 문구 전체가 보이는지 확인한다. 다른 프로젝트 카드의 기존 이미지 중앙 정렬도 회귀 여부를 함께 확인한다.

## Task Team 피드백 초안
- 화면 검증 기준: 홈과 프로젝트 목록의 모바일·태블릿·데스크톱 뷰포트에서 대상 썸네일 상단 카피 전체가 카드 내부에 표시되고 카드 제목과 겹치지 않아야 한다. 데스크톱 홈의 넓은 카드는 별도로 확인하며, 다른 프로젝트 썸네일은 기존 중앙 정렬을 유지해야 한다.

## 검증 및 한계
- typegen·TypeScript, Vitest 32개 파일·423개 테스트, Biome 변경 파일 3개 및 diff 검사가 통과했다.
- 로컬 브라우저에서 390×844, 768×1024, 1440×900의 홈·목록을 확인했고, 모바일·태블릿 목록과 데스크톱 목록·홈 스크린샷에서 카피 전체 노출을 직접 확인했다.
- 운영 배포는 하지 않았다.
